// 01 — panoramica

Perché esiste Scadoo

Il progetto nasce da un problema quotidiano: cibo che scade senza essere visto, liste della spesa dimenticate e nessun modo semplice per tenere traccia di quante confezioni di pasta sono rimaste in dispensa. Le app esistenti sul mercato o costano un abbonamento o hanno interfacce sovraccariche.

L'obiettivo di Scadoo è fare poche cose, farle bene e farle in fretta: scansioni un prodotto, l'app recupera nome e marca dal database Open Food Facts, aggiungi la data di scadenza e il gioco è fatto. Due tap. Tutto offline.

La lista della spesa è pensata per uso familiare: un bottone condivide la lista via WhatsApp o iMessage formattata in modo leggibile, pronta per essere usata al supermercato.

Cosa fa l'app

Scansione rapida
Scan barcode → lookup API → form pre-compilato. Il prodotto è in dispensa in 2 tap.
Lookup Open Food Facts
Endpoint italiano poi mondiale. Recupera nome, marca, categoria e immagine automaticamente.
Tracciamento scadenze
Color coding: verde (ok) → giallo (7 giorni) → arancio (3 giorni) → rosso (scaduto).
Posizioni separate
Frigo, Dispensa e Freezer — filtrabili dalla schermata inventario.
Notifiche push intelligenti
Daily digest alle 9:00 con riepilogo scaduti e in scadenza. Nessun server necessario.
Lista della spesa
Spunta, riordina, aggiungi manualmente. Condividi via Share Sheet con un tap.
Controllo quantità
+/− direttamente dalla card. Se la quantità scende a 0 il prodotto viene eliminato.
Offline-first
Tutto su SQLite locale. L'app funziona senza connessione, l'API è opzionale.

Logica di scadenza nel modello

La logica di scadenza è incapsulata direttamente nel modello, senza dipendenze Flutter. Facile da testare e riusare.

Dart lib/models/product.dart 
class Product {
  // ... altri campi ...
  final DateTime? expiryDate;

  /// Giorni mancanti alla scadenza (negativo = già scaduto)
  int get daysToExpiry {
    if (expiryDate == null) return 9999;
    final today = DateTime(
      DateTime.now().year,
      DateTime.now().month,
      DateTime.now().day,
    );
    final expiry = DateTime(
      expiryDate!.year, expiryDate!.month, expiryDate!.day,
    );
    return expiry.difference(today).inDays;
  }

  bool get isExpired       => expiryDate != null && daysToExpiry < 0;
  bool get isExpiringSoon  => expiryDate != null && daysToExpiry >= 0 && daysToExpiry <= 3;
  bool get isExpiringThisWeek => expiryDate != null && daysToExpiry >= 0 && daysToExpiry <= 7;
}

Integrazione Open Food Facts

Il servizio prova prima l'endpoint italiano (prodotti locali più completi), poi cade sul mondiale. La risposta viene normalizzata in un oggetto OpenFoodFactsResult indipendente dal JSON dell'API.

Dart lib/services/openfoodfacts_service.dart 
Future<OpenFoodFactsResult> fetchProduct(String barcode) async {
  // Prova prima l'endpoint italiano, poi il mondiale
  for (final base in [
    'https://it.openfoodfacts.org',
    'https://world.openfoodfacts.org',
  ]) {
    final result = await _fetch('$base/api/v0/product/$barcode.json');
    if (result.found) return result;
  }
  return const OpenFoodFactsResult(found: false);
}

Future<OpenFoodFactsResult> _fetch(String url) async {
  final response = await http
      .get(Uri.parse(url), headers: {'User-Agent': 'Scadoo/1.0'})
      .timeout(const Duration(seconds: 8));

  if (response.statusCode != 200) return const OpenFoodFactsResult(found: false);

  final data = jsonDecode(response.body);
  if (data['status'] != 1) return const OpenFoodFactsResult(found: false);

  final p = data['product'];
  // Preferisce il nome italiano, poi il generico
  final name = p['product_name_it'] ?? p['product_name'];

  return OpenFoodFactsResult(
    name:     name,
    brand:    p['brands']?.split(',').first.trim(),
    imageUrl: p['image_front_url'],
    found:    name != null,
  );
}

Scanner: flusso dal barcode al form

Il lock _processing evita callback multipli dallo stesso frame. L'attesa visiva (dialog di loading) è mostrata durante la chiamata API prima di navigare al form pre-compilato.

Dart lib/screens/scanner_screen.dart 
Future<void> _onDetect(BarcodeCapture capture) async {
  if (_processing) return;          // evita doppi scan
  final barcode = capture.barcodes.firstOrNull?.rawValue;
  if (barcode == null) return;

  setState(() => _processing = true);
  await _controller.stop();          // ferma la camera

  showDialog(/* loading dialog */);

  final result = await OpenFoodFactsService.instance.fetchProduct(barcode);

  Navigator.of(context).pop();      // chiudi loading
  await Navigator.of(context).pushReplacement(
    MaterialPageRoute(
      builder: (_) => AddProductScreen(
        barcode:   barcode,
        apiResult: result,             // pre-compila il form
      ),
    ),
  );
}

Problemi incontrati

Doppio scan involontario dal barcode scanner
Il callback onDetect viene chiamato più volte per lo stesso barcode in pochi millisecondi. Soluzione: flag booleano _processing che blocca i callback successivi finché la navigazione non è completa.
Calcolo giorni alla scadenza: timezone e ora locale
Usare DateTime.now().difference(expiryDate) in ore può dare risultati sbagliati vicino a mezzanotte. Soluzione: normalizzare entrambe le date a DateTime(year, month, day) prima di calcolare la differenza in giorni.
API Open Food Facts: qualità variabile dei dati italiani
Molti prodotti italiani hanno product_name in inglese o vuoto. Soluzione: cascade di fallback — product_name_it → product_name → generic_name_it → generic_name. Se tutto è vuoto, si mostra il barcode e l'utente può inserire il nome manualmente.
Notifiche: aggiornamento dopo ogni modifica alla dispensa
Ogni volta che l'utente aggiunge, modifica o elimina un prodotto, le notifiche schedulate devono essere ricalcolate. Soluzione: cancelAll() + reschedule dentro loadProducts() del provider, così il ciclo è automatico.
SQLite su Flutter: path del database tra piattaforme
Il percorso del database cambia tra iOS e Android. Soluzione: usare getDatabasesPath() di sqflite combinato con path.join() per costruire il percorso corretto su entrambe le piattaforme.
